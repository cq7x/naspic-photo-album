## 1. 模块架构

```
app/
├─ utils/
│  ├─ api.js        服务端接口封装 + 局域网优先探测
│  ├─ hash.js       文件哈希（<20MB 全量，否则头尾采样）
│  ├─ net.js        网络类型判定（WiFi / 移动网络 / 离线）
│  └─ store.js      本地任务与记录持久化（uni.setStorage / SQLite）
├─ sync/
│  ├─ scanner.js    系统相册扫描 + 自定义文件夹遍历
│  ├─ queue.js      并发可控的任务队列 + 指数退避重试
│  ├─ uploader.js   秒传探测 → 分片上传 → 断点续传 → 完成
│  └─ engine.js     ★ 同步引擎：调度 scanner / queue / uploader，维护状态机
├─ store/sync.js    全局同步状态（Vue3 reactive，供设置页与通知栏读取）
└─ pages/backup/    自动备份设置页（v0.9.0）
```

**职责边界**
- `scanner` 只负责"找出哪些文件需要同步"，不碰网络；
- `uploader` 只负责"把一个文件传完"，不关心策略；
- `engine` 负责策略（WiFi？原图？子目录？冲突？重试？）与状态流转。

## 2. 同步状态机

### 2.1 任务级（一个文件夹 = 一个 Task）

```
        ┌────────────────── 用户暂停 / 网络不满足 ─────────────────┐
        ▼                                                          │
     IDLE ──触发(定时/手动/充电/WiFi)──► SCANNING ──► SYNCING ─────┘
      ▲                                      │           │
      │                                      ▼           ▼
      └──────── 全部完成 ◄────────────── 完成/失败 ──► PAUSED
                                                          │
                                             异常(权限丢失/库不可用) ▼
                                                        ERROR
```

### 2.2 文件级（一个文件 = 一个 Record）

```
PENDING ──► HASHING ──► CHECKING ──┬─► SKIPPED(已存在/秒传) ──► DONE
                                   └─► UPLOADING ──► VERIFYING ──► DONE
   │                                     │
   └─► WAITING_WIFI（策略拦截）           └─► FAILED ──指数退避重试(≤5)──► UPLOADING
                                                    └─► GIVE_UP（进失败列表，需手动重试）
```

**状态落盘**：每次迁移都写入本地存储，APP 被杀后重启可从 `PENDING/UPLOADING` 断点继续。

## 3. 增量识别（三级判定）

| 级别 | 判定 | 成本 | 命中结果 |
|---|---|---|---|
| L1 | `local_id`（系统相册 asset id）或 `路径 + mtime + size` 与上次记录一致 | 极低 | 直接跳过 |
| L2 | 计算内容哈希（<20MB 全量 SHA-256；≥20MB 头1MB+尾1MB+size） | 中 | 与本地历史哈希比，相同则跳过 |
| L3 | 将哈希提交服务端 `/upload/check` | 网络 | 命中则**秒传**，零流量 |

```
扫描到文件
  ├─ L1 命中本地记录 → 跳过
  ├─ 否则计算 hash
  │    ├─ L2 命中本地历史 → 跳过
  │    └─ L3 请求服务端 → 命中：标记 SKIPPED（秒传）；未命中：进入上传队列
```

> Android 系统相册还额外维护 `sync_cursor`（`MediaStore.DATE_MODIFIED` 秒级时间戳），下次只查 mtime > cursor 的媒体，避免每次全量遍历几万张。

## 4. 自定义文件夹独立策略

每个文件夹一条 `SyncTask`，字段：

```js
{
  id, deviceId,
  folderUri,        // Android: SAF tree URI / 绝对路径；iOS: 相册集合 id 或安全书签
  folderPath,       // 展示用可读路径
  folderType,       // 1=系统相册 2=自定义文件夹
  enabled,          // 是否启用
  wifiOnly,         // 仅 WiFi（默认 true）
  uploadOriginal,   // 原图（默认 true）
  includeSubdir,    // 递归子目录（默认 true）
  fileTypes,        // ['image','video']
  syncCursor,       // 增量游标
}
```

**策略生效顺序**（engine 决策树）：

```
任务 enabled?           否 → 跳过
当前网络 = WiFi?        否 且 wifiOnly=true → 置 WAITING_WIFI，等待网络变化事件
fileTypes 包含该类型?   否 → 跳过
includeSubdir?         否 → 只取当前层文件
uploadOriginal?        否 → 先本地压缩（长边 1920、质量 82）再上传
```

## 5. 断点续传

```
uploader.upload(file, task):
    hash = await hashFile(file)
    chk  = await api.uploadCheck({libraryId, hash, size})
    if chk.exists          → 秒传，标记 SKIPPED(已存在)
    if chk.resumable       → sessionId = chk.session_id, done = chk.uploaded_chunks
    else                   → init = api.uploadInit({...}); sessionId = init.session_id; done = []

    for (i = 0; i < chunkTotal; i++):
        if (done.includes(i)) continue          // 断点续传核心
        await retry(() => api.uploadChunk(sessionId, i, slice(file, i)))
    await api.uploadComplete({sessionId})
```

- 分片大小：WiFi 4MB / 移动网络 1MB（服务端在下发 init 时会校正）
- 单次失败：指数退避 `min(30s, 2^n s)`，最多 5 次
- 服务端会话 TTL 7 天，超时后重新 init（已传分片作废）

## 6. 冲突与安全策略

| 场景 | 处理 |
|---|---|
| 服务端已存在**相同哈希** | 不重复存储，返回 `dedup=true`，本地标记完成（双方各保留自己的文件） |
| 服务端存在**同名不同内容** | 服务端自动重命名为 `name (1).jpg`，返回 `renamed=true`，**双方文件都保留** |
| 手机端文件被修改后重传 | 哈希变化 → 视为新文件，服务端不覆盖旧记录 |
| **删除手机本地原图** | **默认绝不执行**。服务端的删除操作只在云端生效，APP 不调用任何本地删除 API |
| 云端删除 | 只删服务端索引/托管文件；挂载库（只读）连物理删除都不允许 |

## 7. 局域网优先传输

```
api.resolveBase():
    candidates = [
      lastLanIP  ? `http://${lastLanIP}:8080`  : null,
      savedPublic ? `https://${savedPublic}`   : null,
    ]
    并行探活（HEAD /api/v1/health，超时 800ms），取最先成功者
    命中 LAN 则本次会话锁定 LAN 通道，并上报 lastLanIP 给服务端
```

> 未命中时自动回落到公网域名；每次同步开始重新探测，适应"在家 LAN / 出门公网"的切换。

## 8. 后台保活与权限坑

### Android

| 坑 | 表现 | 处理 |
|---|---|---|
| Android 13+ 细粒度媒体权限 | 只能读部分照片 | 动态申请 `READ_MEDIA_IMAGES` / `READ_MEDIA_VIDEO`，被拒则引导去设置页 |
| Android 11+ 分区存储 | 无法用绝对路径访问任意目录 | 自定义文件夹走 **SAF（`ACTION_OPEN_DOCUMENT_TREE`）** + `takePersistableUriPermission` 持久化授权 |
| 后台被系统杀死 | 同步中断 | 前台服务 + 常驻通知（显示进度）；引导用户关闭电池优化（`ACTION_REQUEST_IGNORE_BATTERY_OPTIMIZATIONS`） |
| 厂商自启动限制（小米/华为/OPPO） | 重启后不再同步 | 检测到未加入白名单时弹出图文引导 |
| Doze 模式 | 夜间不同步 | 使用 `WorkManager` 周期任务 + 充电时触发 |

### iOS

| 坑 | 表现 | 处理 |
|---|---|---|
| 后台没有真正的常驻 | 只能跑有限时长 | 使用 `BGTaskScheduler` + `BGProcessingTask`，在充电+WiFi 时由系统调度 |
| 相册权限 `NSPhotoLibraryUsageToken` | 首次弹窗 | 使用 `limited` 模式也支持，引导用户升级为 `authorized` |
| 文件夹选择 | 无全局文件树 | 自定义文件夹通过 `UIDocumentPickerViewController` 选目录并保存 **security-scoped bookmark** |
| 后台刷新被用户关闭 | 完全不触发 | 检测 `UIApplication.backgroundRefreshStatus` 并引导去设置 |

### 通用

- 同步状态写入本地存储，进程被杀后重启自动恢复；
- 进度通过通知栏（Android）/ 本地通知（iOS）展示；
- 同步日志保留最近 500 条，设置页可查看与导出。

## 9. 核心伪代码（engine）

```js
async function runTask(task) {
  if (!task.enabled) return
  if (task.wifiOnly && !net.isWifi()) { setState(task, 'WAITING_WIFI'); return }

  setState(task, 'SCANNING')
  const files = await scanner.scanFolder(task)      // L1/L2 增量过滤
  setState(task, 'SYNCING')

  await queue.runLimit(files, /*concurrency*/ 2, async (file) => {
    const rec = store.findRecord(task.id, file.path)
    if (rec && rec.state === DONE && rec.mtime === file.mtime) return // L1 命中

    const hash = await hashFile(file)                                  // L2
    if (rec && rec.hash === hash) { store.touch(rec); return }

    try {
      const r = await uploader.upload(file, task, hash)                // L3 + 分片
      store.markDone(rec, r.mediaId, hash)
    } catch (e) {
      store.markFailed(rec, e, retryCount)
    }
  })

  task.syncCursor = nowSeconds()
  await api.upsertSyncTask(task)      // 上报服务端，便于 Web 端查看
  setState(task, 'IDLE')
}
```

## 10. 关键参数默认值

| 参数 | 默认 | 说明 |
|---|---|---|
| 并发上传数 | 2（WiFi）/ 1（移动网络） | 防止手机发热与服务端压力 |
| 分片大小 | 4MB / 1MB | WiFi / 移动网络 |
| 重试次数 | 5 | 指数退避，上限 30s |
| 全量哈希阈值 | 20MB | 超过走头尾快速哈希 |
| 扫描触发 | 每 30 分钟 + 充电 + 连上 WiFi | 系统调度，非自建死循环 |
| 日志保留 | 最近 500 条 | 设置页可导出 |
