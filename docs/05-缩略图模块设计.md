## 1. 模块设计

```
请求 GET /api/v1/media/:id/thumb?size=md
        │
        ▼
thumb.Service.Get(ctx, drv, key, size)
        │
   ├─① 查 media_files（library_id + relative_path）取 hash
   ├─② 缓存路径 = <cache>/thumbs/<lib>/<hash[:2]>/<hash>/<size>_<px>.webp
   │        └─ 命中磁盘 → 直接返回（零 CPU）
   ├─③ 未命中 → 单飞锁（同一文件并发只生成一次）
   ├─④ 调 Generator 生成（vips / go）
   │        ├─ 成功 → 写缓存 + 落 thumbnails 表 + media.thumb_status=1
   │        └─ 失败 → media.thumb_status=2（后续不再重试，避免死循环）
   └─⑤ 返回字节
```

### 关键设计点

| 点 | 实现 |
|---|---|
| **懒加载** | 只有用户请求才生成；`EnqueueAll` 提供可选的后台补生成，仍走限流队列 |
| **缓存独立** | 缓存目录 `cache_root/thumbs`，与原图彻底分离；可单独挂到 SSD、可随时清空重建 |
| **并发控制** | worker 池默认 2（ARM 低配 1）；libvips 内部线程也压到 1 |
| **单飞** | 同一缓存 key 并发请求只生成一次，其余返回"生成中" |
| **损坏文件** | 生成失败标记 `thumb_status=2`，扫描/浏览不中断 |
| **缓存失效** | 缓存路径含原图 hash，原图变更后自然命中新路径 |

### 尺寸规格

| key | 像素 | 用途 |
|---|---|---|
| `sm` | 256 | 时间轴缩略网格 |
| `md` | 512 | 默认列表 |
| `lg` | 1080 | 大图预览 |
| `sq` | 300 | 方图（人物/相册封面） |

## 2. Golang 调用 libvips 示例

```go
//go:build vips

import "github.com/davidbyttow/govips/v2/vips"

func init() {
    vips.LoggingSettings(nil, vips.LogLevelError)
    vips.Startup(&vips.Config{
        ConcurrencyLevel: 1,        // ARM 低配：内部线程压到 1
        MaxCacheMem:      32 << 20, // 限制 libvips 缓存内存
    })
}

func Generate(src, dst string, size, quality int, format string) error {
    img, err := vips.NewImageFromFile(src)
    if err != nil { return err }          // 损坏文件：直接返回
    defer img.Close()

    // thumbnail_image 利用 JPEG 的 DCT 缩放加载，比全解再缩小快数倍
    if err := img.ThumbnailImage(size, size, vips.InterestingAttention); err != nil {
        return err
    }

    var out []byte
    switch format {
    case "webp":
        out, _, err = img.ExportWebp(&vips.WebpExportParams{Quality: quality, StripMetadata: true})
    default:
        out, _, err = img.ExportJpeg(&vips.JpegExportParams{Quality: quality, StripMetadata: true})
    }
    if err != nil { return err }
    return os.WriteFile(dst, out, 0o644)
}
```

## 3. 格式支持矩阵

| 格式 | libvips 后端 | 纯 Go 降级后端 |
|---|---|---|
| JPEG | ✅ | ✅ |
| PNG | ✅ | ✅ |
| WebP | ✅ 解码 + 编码 | ✅ 解码 / ❌ 编码（自动转 JPEG） |
| GIF | ✅（首帧） | ✅（首帧） |
| HEIC/HEIF | ✅（需 libheif 支持） | ❌ |
| RAW（CR2/NEF/ARW/DNG…） | ✅（仅内嵌预览） | ❌ |
| TIFF | ✅ | ❌ |
| 视频缩略图 | 需 ffprobe/ffmpeg（可选） | ❌ |

> 纯 Go 后端定位是"**能用**"，不是"全支持"。ARM 设备建议老老实实装 libvips。

## 4. ARM 编译 libvips 注意事项

### 4.1 优先走系统包（强烈推荐）

```bash
# Debian / Ubuntu（arm64 官方源已提供）
apt-get update
apt-get install -y libvips-dev          # 约 20MB，比自己编译省 1 小时

# 验证
pkg-config --modversion vips            # 需 >= 8.10
```

### 4.2 包版本太老时自行编译（耗时，慎用）

```bash
apt-get install -y build-essential pkg-config \
    libglib2.0-dev libjpeg-dev libpng-dev libwebp-dev \
    libtiff-dev libheif-dev libexif-dev liblcms2-dev

wget https://github.com/libvips/libvips/releases/download/v8.15.1/vips-8.15.1.tar.xz
tar xf vips-8.15.1.tar.xz && cd vips-8.15.1
meson setup build --prefix=/usr --buildtype=release -Dintrospection=false
ninja -C build && ninja -C build install
ldconfig
```

> 树莓派 4（4GB）编译 libvips 约 25~40 分钟，务必 `ninja -j2` 防止 OOM。

### 4.3 常见坑

| 坑 | 现象 | 解决 |
|---|---|---|
| **交叉编译失败** | cgo 需要目标平台的 C 工具链 | **不要在 amd64 上交叉编译 arm64 的 vips 版本**；用 `docker buildx` 在 arm64 原生环境里构建 |
| `pkg-config: not found` | 构建找不到 vips | `apt install pkg-config`，并设置 `PKG_CONFIG_PATH` |
| `libvips.so.42: cannot open` | 运行时找不到动态库 | 运行镜像里也要装 `libvips42`，或用 `--ldflags '-extldflags "-static"'` 静态链接 |
| **内存爆炸** | 处理 50MP 照片时 OOM | `vips.Startup` 限制 `MaxCacheMem`；并发降到 1；先用 `thumbnail_image` 而非全解 |
| **HEIC 无法解码** | 报 `heif: unsupported` | 安装 `libheif-dev`（>=1.12），且 libvips 编译时要带 heif 模块 |
| **ARM 软浮点** | 部分老设备崩溃 | 使用 `-march=armv8-a` 且不要开 `-mfloat-abi=hard` 的错误组合 |

### 4.4 无 libvips 时的降级

```bash
# 纯 Go 后端（不支持 HEIC/RAW，WebP 只解不编）
go build -o naspic-server ./cmd/server

# libvips 后端（推荐，需本机已装 libvips-dev）
CGO_ENABLED=1 go build -tags vips -o naspic-server ./cmd/server
```

代码通过 build tag 自动选择后端，**没有 libvips 也能正常启动**，只是缩略图能力受限。

## 5. 配置项

```yaml
thumb:
  enabled: true
  backend: vips        # vips | go
  workers: 2           # ARM 低配设 1
  queue_size: 256
  sizes: "256,512,1080"
  quality: 82
  format: webp         # 纯 Go 后端会自动降级为 jpeg
```

## 6. 运维建议

- 缓存目录建议放在**读写频繁不易碎**的位置；SD 卡设备建议改到 USB SSD；
- `thumbnails` 表与磁盘缓存可能不一致（手动删缓存后），直接清空缓存目录即可自愈；
- 批量导入照片后可用 `EnqueueAll(libraryID)` 后台补生成，仍受限流保护，不会打满 CPU。
