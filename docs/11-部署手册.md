# Naspic 私有云相册 — 部署手册（家庭 NAS / ARM 设备）

> 对应 README 场景11 ｜ 版本：v1.0.0
> 面向：树莓派、绿联/海康/群晖等 ARM NAS、x86 小主机的家庭用户

---

## 0. 三十秒速查

```bash
mkdir -p /opt/naspic/data
docker run -d --name naspic --restart unless-stopped \
  -p 8080:8080 -e TZ=Asia/Shanghai \
  -v /opt/naspic/data:/data \
  -v /photos:/photos:ro \
  naspic/naspic:latest
```

浏览器打开 `http://<设备IP>:8080` → 用 `admin / naspic123` 登录 → 立刻改密码。

> **`/photos:/photos:ro` 的 `:ro` 不能去掉。** 这是保护你原始照片的最后一道防线。

## 1. 硬件建议

| 档位 | 典型设备 | 内存 | 建议开关 |
|---|---|---|---|
| 入门 | 树莓派 3B+/4B（2GB）、老 ARM NAS | ≤2GB | SQLite、扫描并发 1、缩略图并发 1、**AI 关闭** |
| 主流 | 树莓派 4B/5（4~8GB）、RK3588 盒子 | 4~8GB | SQLite 或 MySQL、扫描并发 2、AI 可选开 |
| 进阶 | x86 小主机（N100/N305）、群晖/绿联 x86 | ≥8GB | MySQL、并发 4、AI 全开 |

**存储介质建议**

- 系统 + 数据库 + 缩略图缓存：放在 **SSD**（SD 卡随机写会很快写坏）；
- 原照片目录：可留在机械盘 / 网络盘，只读挂载即可；
- 首次扫描 10 万张照片，SD 卡约需 2~4 小时，SSD 约 20~40 分钟。

## 2. Docker 部署

### 2.1 目录规划

```bash
sudo mkdir -p /opt/naspic/data      # 数据库、缓存、临时文件
sudo mkdir -p /mnt/ssd/naspic-cache # 可选：缩略图缓存单独放 SSD
# 你的照片目录（假设）
ls /photos
```

### 2.2 docker run（只读挂载示例）

```bash
docker run -d \
  --name naspic \
  --restart unless-stopped \
  -p 8080:8080 \
  -e TZ=Asia/Shanghai \
  -v /opt/naspic/data:/data \
  -v /mnt/ssd/naspic-cache:/data/cache \   # 可选
  -v /photos:/photos:ro \                   # ← 只读！左右路径保持一致
  naspic/naspic:latest
```

**多个照片目录**

```bash
  -v /photos:/photos:ro \
  -v /mnt/usb/travel:/mnt/usb/travel:ro \
  -v /mnt/nas/family:/mnt/nas/family:ro
```

### 2.3 docker compose

复制 `deploy/docker-compose.yml`，按需修改后：

```bash
docker compose up -d
docker compose logs -f naspic
```

### 2.4 低配 ARM 额外建议

```bash
  --memory=1g --cpus=1.5 \        # 限制资源，避免拖垮整机
  -e NASPIC_TIER=low \            # 强制低配档：并发 1、轮询 600s、AI 关闭
```

## 3. 初始配置

1. 浏览器访问 `http://<设备IP>:8080`
2. 登录 `admin` / `naspic123`，**首次登录后立刻改密码**（设置 → 用户）
3. 添加挂载目录：存储管理 → 添加挂载目录
   - 宿主机路径：填容器内看到的路径，即 `/photos`
   - 访问模式：**只读**（默认，强烈推荐）
   - 变更检测：本地盘选 `inotify`；**NFS/CIFS 网络盘选「定时轮询」**
   - 忽略规则：建议加 `**/@eaDir/**`、`**/.thumbnails/**`、`**/#recycle/**`
4. 点「增量扫描」，在「进度」里看扫描情况
5. 若要手机上传，先新建一个**托管库**（挂载库只读，不能上传）

---

## 4. 手机 APP 接入

1. 安装 APP（Android APK / iOS TestFlight）
2. 打开 APP → 填服务器地址
   - **在家**填内网地址：`http://192.168.1.10:8080`（速度最快，APP 会自动探测局域网）
   - **在外**填公网域名：`https://nas.example.com`（需反代 + HTTPS）
3. 用户名密码登录
4. 授予照片权限（Android 13+ 会分别申请照片/视频权限）

> 建议先在内网配好并跑通一次，再配置外网访问。

---

## 5. 手机文件夹同步配置

1. APP → 自动备份设置 → 打开总开关
2. 系统相册：开关 + 选择「仅 WiFi / 允许流量」「原图 / 压缩」
3. 自定义文件夹：
   - 点「+ 添加」→ 在系统目录选择器里选文件夹（如 `Download/WeChat`）
   - Android 会弹出授权，点「允许」并勾选「始终允许访问此目录」
   - 为该文件夹单独设置：仅 WiFi、原图、包含子目录、上传到哪个库
4. 点「立即同步」验证一次
5. 之后由系统调度自动同步（充电 + WiFi 时优先）

**每个文件夹的配置会实时同步到 Web 端**：存储管理 → 手机设备 → 展开设备可看到进度与失败列表。

## 6. 挂载目录注意事项（**重要**）

| # | 事项 |
|---|---|
| 1 | **一律用 `:ro` 只读挂载**，平台只读模式绝不修改宿主机原图 |
| 2 | 容器内路径与宿主机路径**保持一致**（`/photos:/photos`），否则索引路径会错乱 |
| 3 | SQLite 数据库**必须放在读写卷**（`/data`），不能放到只读挂载点 |
| 4 | **NFS/CIFS**：inotify 不生效，用定时轮询；轮询周期建议 ≥600s |
| 5 | **群晖**：共享目录一般是 `/volume1/photos`，需先在 DSM 里给 Docker 用户读权限 |
| 6 | **绿联/极空间**：在「Docker 存储」里手动映射，注意权限开关要打开「只读」 |
| 7 | 特殊目录要加忽略规则：`@eaDir`（群晖缩略图）、`.thumbnails`、`#recycle`、`.DS_Store` |
| 8 | 不要在平台运行期间重命名/移动宿主机原图目录，会导致索引失效（需重建索引） |
| 9 | **读写模式是高危选项**：开启后删除操作会真实删除宿主机文件，需同时打开「允许删除」双开关 |
| 10 | 平台删除挂载库文件 = **只删索引**，宿主机原图永远保留 |

## 7. 常见故障排查清单

| 现象 | 原因 | 处理 |
|---|---|---|
| 打不开网页 | 端口冲突 / 容器没起来 | `docker logs naspic`；`ss -lntp \| grep 8080` |
| 登录后立刻掉线 | 容器重启导致 token 失效 | 重新登录；生产建议改用 JWT 持久化 |
| 添加挂载目录报「路径不存在」 | 容器内看不到该路径 | 确认 compose volumes 已映射且路径一致 |
| 扫描进度一直是 0 | 目录里没有受支持格式 | 检查扩展名白名单与忽略规则是否过严 |
| 扫描极慢 | SD 卡 / 并发过高 / 网络盘 | 改 SSD、降并发、`NASPIC_TIER=low` |
| 新照片不出现（inotify） | 网络盘不支持 inotify | 改用轮询；查看列表里是否显示「轮询(已降级)」 |
| 缩略图全部裂图 | 未编译 libvips 且文件是 HEIC/RAW | 装 libvips 或改用 JPEG 原图；纯 Go 后端不支持 HEIC |
| `attempt to write a readonly database` | SQLite 库放在了只读挂载点 | 把 `/data` 放到读写卷 |
| 手机上传 403 | 目标库是挂载库（只读） | 新建托管库，把同步任务目标改成托管库 |
| 手机上传很慢 | 走了公网 / 分片太大 | 在家用内网 IP；APP 会自动探测局域网 |
| APP 后台不同步 | 被系统杀进程 | Android 加电池白名单 + 自启动；iOS 开后台刷新 |
| 安卓选了文件夹，重启后失效 | 未取得持久化授权 | 重新选择并勾选「始终允许」 |
| 容器内存被 OOM kill | AI/缩略图并发过高 | `--memory=1g`、关 AI、缩略图并发设 1 |
| 照片时间轴错乱 | 时区不对 / EXIF 缺失 | 设 `TZ=Asia/Shanghai`；EXIF 缺失时可在 Web 端手动改拍摄时间 |
| arm64 拉取镜像失败 | 镜像无 arm64 manifest | `docker buildx imagetools inspect naspic/naspic:latest` 确认 |
| 启动报 `libvips.so.42` 缺失 | 运行镜像缺少运行时库 | 用官方镜像；自制镜像需装 `libvips42` |

## 8. 备份与升级

```bash
# 备份（只需备份 /data，原照片在你自己的目录里）
docker stop naspic
tar czf naspic-backup-$(date +%F).tar.gz -C /opt/naspic data
docker start naspic

# 升级
docker pull naspic/naspic:latest
docker compose pull && docker compose up -d

# 缩略图缓存可随时清空，会自动重建，不影响原图
docker exec naspic rm -rf /data/cache/thumbs
```

## 9. 安全建议

- 立刻修改默认密码；
- 公网访问务必套 HTTPS（Nginx + Let's Encrypt），不要直接暴露 8080；
- 定期备份 `/data`（数据库 + 配置）；
- 只读挂载优先，读写模式只在明确需要时开；
- 有公网需求时，建议同时开启路由器的访问频率限制或用 VPN 回家。
