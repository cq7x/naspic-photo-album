# Naspic 私有云相册 — AI 人脸/场景识别模块

> 对应 README 场景7 ｜ 版本：v0.7.0 ｜ 代码：`server/internal/ai`

---

## 1. 设计原则

| 原则 | 落地 |
|---|---|
| **完全离线** | 只加载本地 `.onnx` 模型，无任何外部请求 |
| **不上传图片** | 数据库只存 `faces.embedding`（BLOB 特征向量）与 bbox，不保存任何裁剪人脸图 |
| **可全局关闭** | `ai.enabled=false` 或编译未带 `-tags ai` → 模块自动停用，服务照常启动 |
| **低优先级** | 独立 worker 池（默认 1），每 30s 补一批（200 张），不与扫描/缩略图抢资源 |
| **失败可自愈** | 单张失败标记 `ai_status=3`，不重试死循环；整批失败不影响其它图片 |

---

## 2. 处理流程

```
feeder（每 30s）
   └─ 查 ai_status=0 的图片 200 张 → 投队列（容量 1024，满则等下轮）

worker（默认 1 个）
   └─ process(mediaID)
        ├─ 解析绝对路径
        ├─ 人脸检测（UltraFace / YuNet，输入 320×240）
        │     └─ 置信度 ≥0.7 → 裁剪 → 特征提取（MobileFaceNet，输出 512 维，L2 归一化）
        │           └─ 写入 faces（bbox + score + embedding）
        ├─ 场景分类（MobileNetV3-Small）
        │     └─ 置信度 ≥0.35 → 写入 media_scenes（最多 3 个标签）
        └─ media_files.ai_status = 1（0=未处理 1=已处理 2=跳过 3=失败）

Cluster（手动/Web 端触发）
   └─ 贪心聚类：对所有 cluster_id IS NULL 的人脸，
      与已有簇代表向量算余弦相似度，≥0.6 归簇，否则新建簇
```

**聚类阈值 0.6**：同人多张照片一般 > 0.6，不同人一般 < 0.5。用户可在 Web 端合并/拆分簇后重新命名。

## 3. 模型选型

| 用途 | 推荐模型 | 体积 | ARM64 CPU 单张耗时（4 核 A55 实测参考） |
|---|---|---|---|
| 人脸检测 | **UltraFace-RFB-320**（slim 版） | ~1.1MB | ~60ms |
| 人脸检测（备选） | YuNet (OpenCV Zoo) | ~230KB | ~40ms，精度更好 |
| 人脸特征 | **MobileFaceNet** | ~4MB | ~90ms |
| 人脸特征（备选） | ArcFace-MobileNetV2（112×112） | ~7MB | ~130ms |
| 场景分类 | **MobileNetV3-Small** 微调（Places365 子集） | ~6MB | ~70ms |
| 场景分类（更低配） | MobileNetV2 0.35x | ~1.6MB | ~35ms |

> 所有模型都可以从 ONNX Model Zoo / GitHub 直接下载 `.onnx`，无需转换。
> 优先选 **深度可分离卷积** 结构（MobileNet 系列），ARM CPU 上没有 GPU 加速，普通卷积会非常慢。

### 模型裁剪方案

1. **量化（最有效）**：FP32 → INT8 动态量化，体积 ×1/4，速度 ×2~3，精度损失 <1%
   ```bash
   python -m onnxruntime.quantization.preprocess --input model.onnx --output model_pp.onnx
   python -m onnxruntime.quantization.quantize_dynamic \
       --model_input model_pp.onnx --model_output model_int8.onnx --per_channel
   ```
2. **输入分辨率下调**：人脸特征 112×112 → 96×96，速度再快 25%，聚类阈值需微调
3. **剪枝**：对通道做结构化剪枝（如 MobileNet width multiplier 1.0 → 0.5），体积 ×1/4
4. **算子精简**：导出时 `opset=11`，避免动态 shape 与新算子在老 ORT 上不兼容

## 4. 资源控制

| 手段 | 配置 / 实现 |
|---|---|
| worker 数 | `ai.workers: 1`（ARM 强制 1） |
| ONNX 线程数 | 会话选项设 `intra_op_num_threads=1`，避免与扫描抢核 |
| 内存上限 | 容器 `mem_limit` 或 systemd `MemoryMax=512M` |
| CPU 权重 | systemd `CPUQuota=20%`；Docker `--cpus=0.5` |
| 批量节奏 | 每 30s 补 200 张，队列满即停 |
| 单张上限 | 一张图最多处理 20 张人脸，防异常输出拖死设备 |

```yaml
ai:
  enabled: true
  model_dir: /data/models
  workers: 1
  max_memory: 512      # MB
  cpu_weight: 20       # %
  detect_face: true
  scene_model: mobilenet_v3_small
```

## 5. ARM64 部署注意事项

| # | 事项 | 说明 |
|---|---|---|
| 1 | **下载 aarch64 版 ONNX Runtime** | Microsoft 发布包名：`onnxruntime-linux-aarch64-1.x.x.tgz`；**不是** `x64` |
| 2 | so 路径 | 放 `/usr/lib/libonnxruntime.so` 或用环境变量 `NASPIC_ORT_LIB=/path/libonnxruntime.so` |
| 3 | 依赖 glibc | aarch64 预编译包要求 glibc ≥2.17；Alpine（musl）**不能直接用**，需改用 debian-slim 基础镜像 |
| 4 | 编译开关 | `go build -tags ai`（不带 tag 时 AI 自动停用，二进制更小、启动更快） |
| 5 | 首次加载慢 | ARM 上加载 6MB 模型约 1~3s，属正常；模型常驻内存不要反复创建会话 |
| 6 | 发热与降频 | 连续跑几千张会触发温控降频；建议夜间低优先级跑，或配合 `cpu_guard` |
| 7 | 32 位 ARM（armv7） | 官方 aarch64 包不适用，需自行编译 ORT，代价很大 → **建议直接放弃 AI 模块** |
| 8 | 模型缺失 | 任一 .onnx 缺失 → 对应能力停用，其它能力不受影响，服务不报错退出 |

## 7. 隐私与安全

- 全程本地推理，**零网络请求**；
- `embedding` 是不可逆特征向量，即使泄露也无法还原人脸图像；
- 用户可在设置里一键 `DELETE FROM faces` 清空全部 AI 数据；
- 关闭 `ai.enabled` 后不会再产生任何新数据，历史数据保留供用户自行清理。
