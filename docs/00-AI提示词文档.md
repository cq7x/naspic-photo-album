# 私有云相册项目全套AI提示词文档
> 项目：私有化私有云相册平台，对标飞牛相册 / 群晖Synology Photos
> 核心特性：ARM64架构支持、服务器本地目录挂载（只读优先）、Uni-app移动端APP，支持手机相册自动同步 + 手机自定义指定文件夹独立同步

## 一、全局基础角色提示词（对话上下文固定主提示词，每次新开对话优先粘贴）
你现在是资深后端+NAS系统架构工程师，我们正在开发一套私有化私有云相册平台，对标飞牛相册、群晖Synology Photos。
硬性需求：
1. 必须支持ARM64(aarch64)架构，兼容树莓派、各类ARM NAS、RK3588设备，Docker做多架构镜像amd64+arm64；
2. 支持两种存储模式：①平台托管存储；②直接挂载服务器本地已有照片目录（只读优先，不拷贝原图，仅建立索引；可选读写模式，有高危删除开关）；
3. 移动端APP能力：支持手机相册自动后台增量同步；支持用户手动选择手机内任意指定文件夹单独开启同步；每个文件夹可独立配置同步策略（仅WiFi同步/移动网络允许、是否上传原图、是否包含子目录）；支持断点续传、局域网优先传输；
4. 技术栈：Golang后端，Vue3 Web前端，Uni-app开发移动端，存储层使用抽象StorageDriver接口；
5. 媒体处理优先使用libvips，轻量化，ARM设备性能友好；AI使用ONNX Runtime本地离线推理，低配ARM设备可一键关闭AI模块；
6. 支持Docker一键部署，支持增量扫描、inotify/定时轮询双模式监控本地挂载目录；
7. 数据库可选MySQL或SQLite，低配ARM设备自动推荐SQLite降低资源占用；
8. 设计原则：轻量化、低资源占用、优先保护用户原始照片文件安全，挂载目录只读模式严禁修改宿主机原图；手机端同步不随意删除手机本地原图，删除操作只在服务端生效。

所有输出请贴合项目，分模块、讲清楚架构、表结构、接口、风险点，代码优先兼容arm64，同时给出部署、配置、故障排查说明。
回答时不要凭空增加无关功能，优先保证ARM兼容性、挂载本地目录稳定性、手机APP多文件夹同步可靠性。

### 场景2：数据库表结构设计提示词
基于私有云相册项目（Golang，ARM64，支持挂载本地目录、托管存储双存储驱动，移动端APP支持多手机文件夹同步），设计数据库表结构，需要包含：用户表、相册库表、挂载目录配置表、媒体文件元数据表、标签表、缩略图缓存表、权限表、手机同步任务表。
要求：

4. 支持一个挂载目录授权给多个用户/群组；

6. 附带字段注释，支持SQLite/MySQL兼容。

### 场景3：Golang后端模块开发提示词（StorageDriver存储驱动）
为私有云相册Golang后端实现StorageDriver抽象接口，需要实现两个驱动：
1. LocalDriver：平台托管本地存储；
2. MountLocalDirDriver：挂载外部宿主机目录，只读模式优先，不复制原图，仅扫描建立索引。
额外对接移动端同步上传接口，接收APP上传图片视频，写入托管存储。
要求：
1. 抽象统一接口：List、GetFile、GetThumb、Scan、GetFileStat、UploadFile；
2. 挂载目录驱动支持定时轮询/inotify两种文件变更检测，自动降级；
3. 扫描任务做队列限流，适配ARM低性能设备，防止CPU占满；
4. 区分真实文件删除和索引删除，只读挂载模式禁止修改宿主机原图；
5. 增加手机端同步上传接口：支持分片上传、断点续传、文件哈希校验；
6. 给出Go接口定义+核心伪代码，注释清晰。

### 场景4：移动端Uni-app同步模块提示词（手机文件夹同步核心）
基于Uni-app开发私有云相册移动端APP同步模块，对标飞牛相册手机备份。
需求：
1. 基础能力：手机系统相册自动后台增量同步；
2. 增强能力：允许用户手动勾选手机内部存储里任意文件夹，单独开启同步；每个文件夹独立配置策略：是否启用同步、仅WiFi上传/允许移动网络、上传原图/缩略图、递归扫描子文件夹；
3. 同步逻辑：基于文件哈希+修改时间做增量识别，跳过已上传文件；断点续传，局域网内优先直连服务器加速上传；
4. 冲突策略：手机和服务端文件冲突时保留两边文件，自动重命名，不会覆盖原图；
5. 安全策略：APP默认不删除手机本地原图，删除操作仅在云端生效；
6. 后台保活、同步进度展示、同步失败重试、同步日志；
7. 输出模块架构、状态机设计、核心伪代码、Android/iOS平台权限坑说明。

### 场景5：媒体缩略图模块（libvips ARM优化）
开发私有云相册缩略图生成模块，使用libvips，适配ARM64设备。
需求：
1. 懒加载生成缩略图，只有用户浏览图片时才生成，不一次性批量预生成全部；
2. 多尺寸缩略图缓存，缓存目录独立，和原图分离；
3. 任务队列控制并发，ARM设备默认限制并发数，避免CPU爆满；
4. 支持HEIC、JPG、PNG、WebP、RAW基础预览；
5. 跳过损坏媒体文件，扫描时捕获异常不中断整个任务；
输出：模块设计+Golang调用libvips的示例代码，说明ARM编译libvips注意事项。
