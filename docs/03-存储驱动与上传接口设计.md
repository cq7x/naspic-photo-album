## 1. 抽象接口定义

```go
// server/internal/storage/driver.go
type StorageDriver interface {
    Kind() DriverKind                 // managed | mounted
    Writable() bool                   // 挂载只读模式恒 false
    Root() string

    List(ctx, opt ListOption) ([]Entry, error)
    GetFile(ctx, key string) (io.ReadCloser, error)
    GetThumb(ctx, key string, size ThumbSize) ([]byte, string, error)
    Scan(ctx, opt ScanOption) (<-chan ScanEvent, error)
    GetFileStat(ctx, key string) (*FileStat, error)
    UploadFile(ctx, r io.Reader, opt UploadOption) (*UploadResult, error)
    Delete(ctx, key string, deletePhysical bool) error
}
```

### 驱动行为对照

| 能力 | LocalDriver（托管） | MountLocalDirDriver（挂载） |
|---|---|---|
| Kind | `managed` | `mounted` |
| Writable | `true` | `mode==2` 时 true，默认 `false` |
| UploadFile | 落盘到 `managed_root` | **直接返回 `ErrReadOnly`** |
| GetFile | 读托管目录 | **只读打开宿主机文件**，不复制不修改 |
| Delete(physical=false) | 只删索引 | 只删索引（唯一允许的方式） |
| Delete(physical=true) | 删物理文件 | 需 `mode==2 && allow_delete`，否则 `ErrReadOnly` |
| 变更检测 | 定时增量扫描 | inotify 优先，**失败自动降级轮询** |

## 2. 核心伪代码

### 2.1 只读挂载的第一道闸门

```go
func (d *MountLocalDirDriver) UploadFile(...) (*UploadResult, error) {
    return nil, ErrReadOnly          // 挂载库永不接受上传
}

func (d *MountLocalDirDriver) Delete(ctx, key string, deletePhysical bool) error {
    if !deletePhysical {
        return nil                    // 只删索引，宿主机原图原封不动
    }
    if !d.Writable() || !d.cfg.AllowDelete {
        return ErrReadOnly            // 双开关：读写模式 + 删除开关
    }
    return os.Remove(safeJoin(d.root, key))
}
```

### 2.2 扫描事件流（不中断）

```
WalkDir 遍历 → 命中忽略规则/非媒体后缀 → 跳过
             → mtime 早于 Since 且非全量 → EventSkipped
             → 计算哈希（<20MB 全量，否则头1MB+尾1MB+size）
             → EventCreated / EventUpdated
读取/哈希异常 → EventError（记录日志，继续下一个文件）
源文件消失   → EventMissing（只把 index_status 置为 2，不删任何磁盘文件）
```

> 关键：**单个文件异常绝不终止整个扫描任务**，错误写入 `scan_logs` 由 Web 端展示。

### 2.3 inotify / 轮询双模式与自动降级

```go
func (d *MountLocalDirDriver) Watch(ctx) (<-chan ScanEvent, error) {
    if cfg.WatchMode == WatchInotify {
        w, err := fsnotify.NewWatcher()
        if err == nil && d.addWatchRecursive(w, d.root) == nil {
            go d.watchLoop(ctx, w, out)   // inotify 成功
            return out, nil
        }
        d.degraded = true                 // 标记降级，Web 端可展示告警
    }
    go d.pollLoop(ctx, out)               // 轮询兜底
    return out, nil
}
```

降级常见触发场景：
- 挂载点是 **NFS / CIFS / SMB**（inotify 不跨网络文件系统生效）
- 容器 overlayfs 层数过多、`max_user_watches` 耗尽
- 部分 ARM 内核裁剪掉了 inotify 支持

**轮询参数建议**：目录 < 5 万文件 → 300s；> 20 万文件 → 900s；低配 ARM → 600s 起。

### 2.4 扫描队列限流（ARM 防 CPU 打满）

```
Submit(JobRequest)
   ├─ 同一库已在扫描 → ErrJobRunning（409）
   └─ 有界队列（默认 512）→ worker 池（ARM 默认 1~2）

worker:
   批次入库（默认 200~300 条/批）
      ├─ 令牌桶 rate_per_sec（ARM 默认 2~5）
      ├─ CPU 守护：loadavg > cpu_limit × NumCPU → sleep 500ms 退避（最多 30s）
      └─ Upsert on conflict(library_id, relative_path) 保证幂等
```

> Upsert 只更新 `size_bytes / hash / index_status / ext / media_type`，**不覆盖 `taken_at`**，避免重复扫描把用户手动修正的拍摄时间冲掉。

### 2.5 手机端同步上传接口（分片 + 断点续传 + 哈希校验）

```
① POST /api/v1/upload/check   {library_id, hash, size}
     ├─ 命中 hash          → {exists:true, media_id}        秒传，0 流量
     └─ 命中未完成 session  → {resumable:true, session_id, uploaded_chunks}

② POST /api/v1/upload/init    {library_id, hash, size, filename, network}
     → {session_id, chunk_size(4MB WiFi / 1MB 移动网络), chunk_total}
     → 服务端建 tmp 目录 + upload_sessions 记录（TTL 7 天）

③ PUT /api/v1/upload/chunk?session_id=xx&index=n   （body = 分片原始字节）
     → 写 part_%06d 文件，回传已上传分片列表
     → 断线重连后按 uploaded_chunks 只补缺失分片

④ POST /api/v1/upload/complete {session_id}
     → 按序合并 → SHA-256 校验（不符直接报哈希错误，不入库）
     → 二次查重（防并发重复）→ 写入托管库 → 解析 EXIF → 入库 media_files
     → 清理 tmp，会话置为已完成
```

**冲突不覆盖**：`UploadFile` 若目标路径已存在且 `Overwrite=false`，自动重命名为 `name (1).jpg`，返回 `renamed=true`。

## 4. 风险点与部署注意

| # | 风险 | 应对 |
|---|---|---|
| 1 | `host_path` 路径穿越 | `SafeJoin` 统一做 `path.Clean` + 前缀校验，拒绝 `../` |
| 2 | 挂载点未挂载时启动 | 驱动初始化检测目录不存在直接报错，不建空索引 |
| 3 | SQLite 写入锁竞争 | WAL + `busy_timeout=5000` + 批量分片提交 |
| 4 | 大目录首次扫描耗时长 | 可后台跑，Web 端展示进度；支持暂停后继续 |
| 5 | 容器内路径与宿主机不一致 | 文档与 compose 强制左右路径一致（`/photos:/photos:ro`） |
| 6 | 分片 tmp 目录膨胀 | 会话 TTL 到期清理 + 每日定时任务清理孤儿 tmp |
| 7 | APP 上传打到挂载库 | `/upload/init` 检查 `Writable()`，只读库返回 403 |

## 5. 编译与运行

```bash
cd server
go mod tidy

# 本机（amd64）
go build -o naspic-server ./cmd/server

# 交叉编译 arm64（纯 Go SQLite，无需 cgo）
GOOS=linux GOARCH=arm64 CGO_ENABLED=0 go build -o naspic-server-arm64 ./cmd/server

# 运行
cp config.example.yaml config.yaml
./naspic-server -c config.yaml
```

> SQLite 选用 `glebarez/sqlite`（纯 Go 实现），避免 `mattn/go-sqlite3` 的 cgo 交叉编译负担——这是 ARM 打包最大的坑之一。
