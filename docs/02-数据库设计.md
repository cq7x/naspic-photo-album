# Naspic 私有云相册 — 数据库设计

> 对应 README 场景2
> 版本：v0.2.0 ｜ 兼容：SQLite 3.35+ / MySQL 5.7+（8.0 推荐）｜ ORM：GORM

---

## 0. 设计前提

| 项 | 约定 |
|---|---|
| 主键 | `BIGINT` 自增（SQLite 为 INTEGER PK AUTOINCREMENT 表现一致） |
| 时间 | 统一存 **UTC**，字段名 `*_at`，类型 `DATETIME` |
| 布尔 | `TINYINT(1)`（MySQL）/ `INTEGER`（SQLite），GORM 统一映射 bool |
| JSON | `TEXT` 存 JSON 字符串（兼容两者，避免 MySQL 5.7 JSON 差异） |
| 软删 | 统一 `deleted_at` 可空，索引含 `deleted_at` |
| 区分 | `source_type`：**1=托管存储文件 / 2=挂载目录索引文件** |

### 2.3 mount_dirs — 挂载目录配置表

| 字段 | 类型 | 说明 |
|---|---|---|

| media_type | TINYINT | 1=图片 2=视频 3=其他 |
| width / height | INT | |
| duration_ms | INT | 视频 |
| orientation | SMALLINT | EXIF Orientation |
| taken_at | DATETIME | 拍摄时间（EXIF → mtime 兜底） |

| exif_json | TEXT | 完整 EXIF 快照 |
| **index_status** | TINYINT | 1=正常 2=源文件缺失（挂载目录） 3=损坏无法解析 |

**索引设计（面向几十万 ~ 百万级）**

| 索引 | 字段 | 用途 |
|---|---|---|
| `uk_lib_path` | (library_id, relative_path) **UNIQUE** | 增量扫描 upsert 依据 |
| `idx_lib_taken` | (library_id, taken_at DESC, id DESC) | **时间轴主查询** |
| `idx_hash` | (hash) | 秒传、去重 |
| `idx_lib_status` | (library_id, index_status, media_type) | 筛选/统计 |
| `idx_thumb` | (thumb_status, library_id) | 缩略图补生成任务 |
| `idx_ai` | (ai_status, library_id) | AI 待处理扫描 |
| `idx_device` | (uploaded_by_device_id) | 按设备回溯 |

> SQLite 建议：`PRAGMA journal_mode=WAL; PRAGMA synchronous=NORMAL; PRAGMA cache_size=-16000;`
> MySQL 建议：`media_files` 单独 file-per-table，`exif_json` 用 `TEXT` 避免行溢出。

### 2.12 scan_jobs / scan_logs

- `scan_jobs`: id, library_id, type(1=增量 2=全量重建), trigger(1=手动 2=定时 3=inotify), status(1=排队 2=运行中 3=完成 4=失败 5=取消), total, scanned, added, updated, missing, failed, started_at, finished_at, error
- `scan_logs`: id, job_id, level(1=info 2=warn 3=error), path, message, created_at

## 3. 性能与运维要点

1. **时间轴分页**：用 `(taken_at, id)` 游标分页，避免 `OFFSET` 深翻页；
2. **计数**：`media_count` 冗余字段 + 扫描结束批量更新，避免高频 `COUNT(*)`；
3. **批量写入**：扫描入库用 `UPSERT` 批量（每批 200~500），事务包裹；
4. **SQLite 锁**：WAL + 单写连接 + `busy_timeout=5000`，扫描大批量时分片提交；
5. **清理**：`scan_logs`、`upload_sessions` 过期记录由每日定时任务清理；
6. **迁移**：SQL 迁移文件放在 `server/migrations`，启动时自动执行（带版本号表 `schema_migrations`）。
