# Naspic 私有云相册 — 需求与方案设计

> 对应 README 场景1：`V1.0 MVP 功能清单`
> 版本：v0.1.0 ｜ 架构：Golang 后端 + Vue3 Web + Uni-app 移动端 ｜ 目标架构：amd64 + arm64

---

## 0. 一句话定位

一套**私有化、轻量、ARM 友好**的相册平台。核心差异化：
1. **不动原图**——挂载服务器已有照片目录，只读索引，绝不修改宿主机文件；
2. **手机多文件夹独立同步**——系统相册自动备份 + 任意自定义文件夹单独配置策略；
3. **低配可跑**——SQLite 默认、libvips 轻处理、AI 可一键关闭。

## 2. 模块设计

```
naspic
├─ server/                    Golang 后端（单二进制）
│  ├─ cmd/server              入口
│  ├─ internal/config         配置（YAML + 环境变量覆盖）
│  ├─ internal/model          GORM 模型（SQLite / MySQL 双兼容）
│  ├─ internal/store          数据库初始化 + 迁移
│  ├─ internal/storage        ★ StorageDriver 抽象
│  │  ├─ driver.go            接口定义
│  │  ├─ local.go             LocalDriver（托管）
│  │  └─ mount.go             MountLocalDirDriver（挂载/只读）
│  ├─ internal/scanner        扫描调度：队列 + 限流 + inotify/轮询
│  ├─ internal/thumb          libvips 缩略图（cgo，可 build tag 关闭）
│  ├─ internal/ai             ONNX Runtime（可 build tag 关闭）
│  ├─ internal/syncsvc        手机同步会话、游标、冲突处理
│  └─ internal/api            Gin 路由与 Handler
├─ web/                       Vue3 + Element Plus 管理/浏览端
├─ app/                       Uni-app 移动端（Android / iOS）
└─ deploy/                    Dockerfile / buildx / compose
```

### 2.1 核心抽象：StorageDriver

```go
type StorageDriver interface {
    Kind() DriverKind                                  // managed | mounted
    List(ctx, dir string, opt ListOption) ([]Entry, error)
    GetFile(ctx, key string) (io.ReadCloser, error)    // 原图流（挂载模式直读宿主机）
    GetThumb(ctx, key string, size ThumbSize) ([]byte, error)
    Scan(ctx, opt ScanOption) (<-chan ScanEvent, error)
    GetFileStat(ctx, key string) (*FileStat, error)
    UploadFile(ctx, r io.Reader, opt UploadOption) (*UploadResult, error) // 仅 managed
    Writable() bool                                    // 挂载只读模式返回 false
}
```

- **managed**：`UploadFile` 可用，`Writable() == true`
- **mounted**：`UploadFile` 直接返回 `ErrReadOnly`，删除只删索引不删宿主机文件

### 2.2 扫描调度

```
扫描触发源 ──► scanQueue（有界队列，ARM 默认容量 512）
                    │
                    ├─ 令牌桶限流（默认 5 tasks/s，ARM 建议 2）
                    ├─ 并发 workers（默认 min(2, CPU/2)，ARM 强制 ≤2）
                    └─ CPU 守护：loadavg > 阈值时自动 sleep 退避
```

事件类型：`created / updated / deleted / skipped / error`，写入 `scan_log` 表。

### 2.3 上传链路（APP → 服务端）

```
APP 计算文件 SHA-256
   ├─ POST /api/v1/upload/check   → 命中则秒传（返回已存在 media_id）
   └─ 未命中 → POST /api/v1/upload/init（拿 upload_id + 已传分片列表）
              → PUT  /api/v1/upload/chunk?index=n（并发 ≤3，失败重试）
              → POST /api/v1/upload/complete（服务端合并 + 校验哈希 + 入媒体库）
```

## 3. 手机端同步逻辑与冲突处理

### 3.1 增量识别（三级判定，逐级加重）

| 级别 | 判定依据 | 成本 | 说明 |
|---|---|---|---|
| L1 | `local_id`（系统相册 asset id / 文件路径）+ 修改时间 + 大小 | 极低 | 命中即跳过 |
| L2 | 文件路径 + SHA-256 | 中 | L1 未命中时计算哈希 |
| L3 | 服务端哈希查重 | 中 | 命中 → 直接关联，秒传 |

> 哈希计算策略：文件 < 20MB 全量哈希；≥ 20MB 取「头 1MB + 尾 1MB + size」组合哈希，兼顾速度与碰撞风险。

### 3.2 同步状态机（单文件）

```
PENDING ──► HASHING ──► CHECKING ──┬─► DONE(秒传)
                                   └─► UPLOADING ──► VERIFYING ──► DONE
       └─► WAITING_WIFI ──► (网络就绪) ──► UPLOADING
       └─► FAILED ──► (指数退避重试 ≤5 次) ──► UPLOADING
                                          └─► GIVE_UP（进失败列表）
```

任务级状态：`IDLE → SCANNING → SYNCING → PAUSED → IDLE`，支持用户暂停/恢复。

### 3.3 冲突处理（**永不覆盖**）

同一文件（`hash` 相同但 `local_path` 不同，或同名不同内容）上传时：

1. 服务端已存在**相同哈希** → 不重复存储，新建 media 记录指向同一对象，返回 `dedup`；
2. 服务端存在**同名但内容不同** → 保留双方，服务端自动重命名为 `name (1).jpg`，返回 `renamed`；
3. **绝不删除手机本地原图**：APP 侧删除操作只调用服务端删除接口（且仅对托管库生效），本地文件不动；
4. 挂载库中的文件**不允许从 APP 删除**（只读模式），服务端返回 `409 LIBRARY_READONLY`。

### 3.4 断点续传

- 分片大小：默认 4MB（WiFi）/ 1MB（移动网络）
- 服务端记录 `upload_session.uploaded_chunks`，APP 重连后拉取已传分片，只补缺失部分
- 服务端 session TTL 7 天，过期清理

### 3.5 局域网优先传输

APP 保存「上次可达的局域网地址」，发起同步前先并行探测：
```
探测顺序：LAN_IP:PORT(HTTPS 自签) → LAN_IP:PORT(HTTP) → 公网域名
探测超时 800ms，命中即锁定本次会话使用 LAN 通道
```

## 4. 风险点与 ARM 设备优化

| # | 风险 | 影响 | 应对方案 |
|---|---|---|---|
| R1 | **ARM 编译 libvips 困难** | 缩略图模块不可用 | ① 官方 .deb 优先；② 提供 `novips` build tag 降级到 `imaging` 纯 Go 实现；③ 镜像内预编译并缓存 |
| R2 | **inotify 在部分挂载（NFS/CIFS/overlay）失效** | 文件变更检测不到 | 监听失败/超时自动降级轮询；轮询周期可配；对网络盘默认强制轮询 |
| R3 | **低配 ARM（1GB 内存）OOM** | 服务被 kill | ① SQLite 默认；② 扫描并发 ≤2；③ 缩略图并发 ≤2；④ AI 默认关闭；⑤ 内存上限通过 systemd/docker 限制 |
| R4 | **只读挂载被误写** | 用户原图损坏 | ① 驱动层 `Writable()==false` 硬拦截；② 挂载卷强制 `:ro`；③ 删除操作二次确认 + 高危开关 |
| R5 | **海量文件首次扫描慢** | CPU 长期打满 | 分批（每批 500）+ 令牌桶 + CPU 负载守护 + 可暂停 |
| R6 | **HEIC/RAW 解码耗资源** | ARM 卡顿 | 缩略图走 libvips 的 `thumbnail_image`（利用 JPEG 缩放加载），RAW 仅提取内嵌预览 |
| R7 | **ONNX Runtime ARM 包缺失** | AI 无法启用 | AI 走 build tag + 动态加载 so，缺失时功能自动禁用而非启动失败 |
| R8 | **手机后台被系统杀** | 同步中断 | Android：前台服务 + 电池优化白名单引导；iOS：BackgroundTasks + 有限时长，配合手动触发 |
| R9 | **MySQL 在 ARM 上资源占用高** | 低配设备卡 | 默认 SQLite；初始化向导按内存自动推荐 |
| R10 | **时间/时区导致时间轴错乱** | 照片排序异常 | 统一存 UTC，展示按用户时区；EXIF 缺失时用文件 mtime 兜底 |

### ARM 资源默认档位（按内存自动选择）

| 档位 | 内存 | 扫描并发 | 缩略图并发 | AI | 数据库 |
|---|---|---|---|---|---|
| low | ≤1GB | 1 | 1 | 关 | SQLite |
| mid | 1~4GB | 2 | 2 | 可选 | SQLite |
| high | >4GB | 4 | min(4, CPU/2) | 开 | MySQL 可选 |
